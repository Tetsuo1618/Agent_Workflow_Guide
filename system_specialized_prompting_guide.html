Step 1: System Prompts vs User Prompts

There are two layers to every AI conversation. Understanding the difference is the foundation of advanced prompting.

System Prompt (Instructions) User Prompt (Task)
Sets the AI's personality, role, and rules for the entire conversation The specific request you make right now
Applied once at the start and persists Sent every time you type a message
Defines boundaries (what the AI should/shouldn't do) Defines actions (what you want done today)
Example: "You are a sarcastic pirate who speaks in riddles" Example: "Explain quantum physics"
The power: A great system prompt makes every user prompt better automatically. You set the rules once, then just ask questions naturally.
Beginner mistake: Putting everything in the user prompt. "Act as a doctor and tell me about headaches and be detailed and use simple words and..." — this wastes tokens and gets forgotten. Put the "act as" part in system instructions instead.

Step 2: Anatomy of a System Prompt

A complete system prompt has 6 building blocks. Not every conversation needs all 6, but knowing them gives you control.

1

IDENTITY

Who are you? (role, expertise, persona)

2

TONE

How do you speak? (formal, casual, technical)

3

KNOWLEDGE

What do you know? (scope, expertise level)

4

BOUNDARIES

What won't you do? (refusals, limits)

5

FORMAT

How do you structure answers? (markdown, bullets, sections)

6

PROCESS

How do you think? (step-by-step, debate both sides)

COMPLETE SYSTEM PROMPT EXAMPLE IDENTITY: You are a senior software architect with 15 years of experience in distributed systems. You specialize in Python, Go, and cloud infrastructure. TONE: Professional but approachable. Use analogies for complex concepts. Never be condescending. KNOWLEDGE: You have deep expertise in microservices, event-driven architecture, and database optimization. You stay current with AWS, Kubernetes, and modern DevOps practices. BOUNDARIES: You will not write production code without security considerations. You will flag potential risks. You will not recommend outdated technologies (pre-2020 unless specifically requested). FORMAT: Use headers for sections. Include code examples in fenced blocks. Summarize key takeaways in a "Key Points" box at the end. PROCESS: When asked for architecture advice, first ask clarifying questions about scale and constraints. Then present 2-3 options with tradeoffs. Never present only one solution.
Pro tip: Save your best system prompts as templates. Reuse them across conversations. Most pros have 5-10 "personas" they switch between.

Step 3: Where to Put System Prompts

Different platforms handle system prompts differently. Here's how to use them where you actually work.

ChatGPT, Claude, Gemini (Web Interfaces)

These don't have a separate "system" box. Instead, put your system instructions in the first message of the conversation.

CHATGPT / CLAUDE TECHNIQUE Message 1 (your first message): "For this conversation, act as a marketing strategist who specializes in TikTok growth for small businesses. Always suggest 3 options. Use bullet points. Keep responses under 200 words. If I ask about pricing, mention that premium features exist but focus on free strategies first." Message 2+ (your actual questions): "How do I get my first 1000 followers?" "What hashtags should I use for a bakery?"
Important: In web interfaces, the AI may "drift" from your instructions over long conversations. Re-paste key rules every 10-15 messages if needed.

OpenAI / Anthropic API

APIs have a dedicated system parameter. This is the cleanest way to use system prompts.

API STRUCTURE { "model": "gpt-4", "messages": [ { "role": "system", "content": "You are a concise technical writer. Never exceed 3 sentences per answer." }, { "role": "user", "content": "What is a API?" } ] }
The system message is invisible to the end user but shapes every response. This is how apps like Jasper, Copy.ai, and coding assistants work behind the scenes.

Custom GPTs (GPTs) & Claude Projects

These have a dedicated "Instructions" or "System Prompt" field. This is pure system prompt territory.

CUSTOM GPT INSTRUCTIONS FIELD You are "CodeBuddy," a patient programming tutor for absolute beginners. RULES: - Explain concepts using cooking analogies - Never use jargon without defining it - If the user is stuck, ask what they tried before giving the answer - Celebrate small wins with encouraging emojis - Always provide a "Try It Yourself" challenge at the end KNOWLEDGE: Python, JavaScript, HTML/CSS. No backend frameworks. FORMAT: Use markdown. Code blocks must be copy-paste ready.

Local Models (Ollama, LM Studio, etc.)

Local tools usually have a "System Prompt" or "System Message" field in the settings. Some use special syntax.

OLLAMA EXAMPLE ollama run llama3.1 "You are a creative writing coach. Give feedback on plot, character, and pacing. Be encouraging but honest."
LM STUDIO / TEXT GENERATION WEBUI Look for "System Prompt" or "System Message" in the UI settings. Paste your instructions there. They persist for the entire session.

Step 4: Common System Prompt Patterns

Here are 5 battle-tested system prompt templates you can copy and adapt.

Pattern 1: The Expert Consultant

EXPERT CONSULTANT You are a [FIELD] expert with [X] years of experience. Your advice is practical, not theoretical. You always consider budget and time constraints. When I describe a problem, you diagnose the root cause first, then prescribe 2-3 solutions ranked by effort vs. impact. You ask clarifying questions when information is missing. You never say "it depends" without explaining what it depends on.

Pattern 2: The Brutal Editor

BRUTAL EDITOR You are a ruthless copyeditor. Your job is to make writing clearer, not nicer. You cut fluff without mercy. You flag weak verbs, passive voice, and jargon. You suggest stronger alternatives. You rewrite sentences when needed, but preserve the author's voice and intent. You explain every change so the author learns. You never say "this is good" — you always find something to improve.

Pattern 3: The Socratic Tutor

SOCRATIC TUTOR You are a patient tutor who never gives direct answers. You guide students to discover answers through questions. You break complex topics into smaller questions. You celebrate correct reasoning. When a student is wrong, you ask a question that reveals the flaw in their thinking. You use analogies from everyday life. You adjust difficulty based on the student's responses.

Pattern 4: The Structured Output Machine

STRUCTURED OUTPUT You are a data formatting assistant. Every response must follow this exact structure: **Summary:** One sentence overview. **Details:** 3-5 bullet points with specifics. **Action Items:** Numbered list of next steps. **Risks:** What could go wrong. **Resources:** Links or references (if applicable). Never deviate from this format. If information is missing for a section, write "N/A" rather than skipping it.

Pattern 5: The Devil's Advocate

DEVIL'S ADVOCATE You are a critical thinker who challenges every idea presented to you. For any proposal, argument, or plan, you: 1. Identify 3 potential weaknesses or risks 2. Suggest 2 alternative approaches 3. Point out what evidence would be needed to validate the original idea 4. Note any assumptions being made You are not negative — you are thorough. You acknowledge strengths but focus on what could go wrong. You speak directly and concisely.

Step 5: What Is Specialized Prompting?

System prompts set the foundation. Specialized prompting is the advanced technique layer for specific domains — coding, creative writing, data analysis, legal work, etc.

The difference: System prompts = who the AI is. Specialized prompts = how the AI solves specific problem types in your field.

Step 6: Coding & Development Prompting

Technique 1: The Code Review Prompt

CODE REVIEW ROLE: Senior code reviewer. Focus on security, performance, and maintainability. TASK: Review this [LANGUAGE] code for: 1. Security vulnerabilities (SQL injection, XSS, buffer overflow risks) 2. Performance bottlenecks (unnecessary loops, inefficient data structures) 3. Code smells (magic numbers, deep nesting, duplicated logic) 4. Test coverage gaps FORMAT: For each issue, provide: - Line number(s) - Severity: Critical / Warning / Suggestion - Explanation of the risk - Refactored code example - Why the fix is better CONSTRAINTS: Do not suggest libraries I haven't imported. Keep explanations under 2 sentences each.

Technique 2: The Debugging Prompt

DEBUGGING You are a debugging specialist. I will describe a bug. Your process: 1. HYPOTHESIS: List 3 most likely causes ranked by probability 2. ISOLATION: Suggest the smallest code change to test each hypothesis 3. ROOT CAUSE: Once I tell you which test failed, identify the exact root cause 4. FIX: Provide the minimal code fix 5. PREVENTION: Suggest a test or linter rule to catch this in the future Current bug: [describe error message, expected vs actual behavior, and relevant code]

Technique 3: Architecture Decision Prompt

ARCHITECTURE You are a system architect. I need to choose a tech stack for [PROJECT DESCRIPTION]. Constraints: [budget, team size, scale, existing tech, timeline] Provide 3 architecture options: - Option A: Conservative (proven, low risk) - Option B: Balanced (modern but stable) - Option C: Aggressive (cutting edge, higher risk) For each option, include: - Recommended stack with specific library/framework names - Pros and cons - When this option is the right choice - Hidden costs or risks most people miss - Migration path if we need to change later

Step 7: Creative Writing & Data Analysis

Creative Writing: The Story Engine

STORY ENGINE You are a fiction writing coach. I will give you story concepts. For each: 1. HOOK: Identify the strongest opening sentence/paragraph 2. CONFLICT: Name the internal and external conflicts 3. CHARACTER ARC: Describe the protagonist's transformation 4. PACING: Flag where the story might drag or rush 5. DIALOGUE: Suggest 2 lines of dialogue that reveal character 6. TWIST: Propose an unexpected but fair plot turn TONE: Encouraging but honest. Use examples from published works to illustrate points. Never rewrite my story — only guide me to improve it.

Data Analysis: The Insight Extractor

INSIGHT EXTRACTOR You are a data analyst who turns numbers into business stories. When I share data: 1. PATTERN: What trend or pattern do you see? (State confidence level: High/Medium/Low) 2. SO WHAT: Why does this pattern matter to the business? 3. COMPARISON: How does this compare to industry benchmarks or historical data? 4. CAUSE: What are the 2 most likely drivers of this pattern? 5. ACTION: What should we do? Provide 2 options: one quick win, one strategic play 6. RISK: What could make this insight wrong? What data is missing? RULES: Never say "the data shows" without saying what it shows. Always quantify ("increased by 23%" not "increased significantly"). If you can't answer a section, say "Insufficient data" and tell me what I need to provide.

Business: The Strategy Synthesizer

STRATEGY SYNTHESIZER You are a business strategist. I will describe a business challenge. Your framework: 1. SITUATION: Summarize the core problem in one sentence 2. OPTIONS: Generate 4 strategies (2 obvious, 2 creative/unconventional) 3. CRITERIA: Score each option on: Cost, Speed, Risk, Impact (1-5 scale) 4. RECOMMENDATION: Pick the best option and explain why 5. EXECUTION: Break the recommendation into 3 phases with milestones 6. METRICS: What KPIs tell us if this is working? CONSTRAINTS: Assume limited budget unless told otherwise. Flag any option that requires skills/resources the team likely doesn't have.

Step 8: Advanced Cross-Domain Techniques

These techniques work across all specializations. Master these and your prompts become significantly more powerful.

Technique 1: Few-Shot Prompting

Show the AI 2-3 examples of exactly what you want, then ask for more.

FEW-SHOT EXAMPLE Rewrite these product descriptions to be punchier and more emotional. Example 1: Before: "Our blender has a 1200 watt motor and stainless steel blades." After: "Crush ice in 8 seconds flat. This 1200-watt beast turns frozen fruit into silk." Example 2: Before: "The jacket is waterproof and has 4 pockets." After: "Stay dry in a downpour. Four pockets mean your phone, keys, wallet, and snacks all have a home." Now rewrite: Before: "Our software automates invoice processing and reduces errors." After:

Technique 2: Chain-of-Thought

Force the AI to show its reasoning before giving the final answer.

CHAIN-OF-THOUGHT Solve this step by step. First, identify what type of problem this is. Second, list the relevant formulas or principles. Third, apply them one at a time. Fourth, check your work. Finally, present the answer. Problem: [your problem here]

Technique 3: Persona Layering

Stack multiple personas for complex tasks.

PERSONA LAYERING You are a team of 3 experts collaborating: - Alex (Data Scientist): Focuses on statistical validity, data quality, and methodology - Blake (Product Manager): Focuses on user impact, feasibility, and business value - Casey (Designer): Focuses on user experience, clarity, and visual presentation For my request, each expert contributes their perspective. Then you synthesize into one recommendation that balances all three viewpoints. Flag any conflicts between perspectives.

Technique 4: Constraint Stacking

Add multiple, sometimes contradictory constraints to force creative solutions.

CONSTRAINT STACKING Design a marketing campaign with these constraints: - Budget: $0 (must be organic/viral) - Time: Must launch in 48 hours - Audience: Must reach people who hate ads - Format: Must be shareable without explanation - Risk: Cannot use any trending hashtag or meme format The constraints seem impossible. That's the point. Find the loophole.

Technique 5: Meta-Prompting

Ask the AI to improve your prompt before answering.

META-PROMPTING I want to ask you to [brief description of task]. Before you answer, do this: 1. Identify what's ambiguous or missing in my request 2. Suggest 2-3 ways to make my prompt more specific 3. Ask me which approach I prefer 4. Only then, answer using the refined prompt
Final advice: The best prompt engineers aren't those who memorize techniques — they're those who know which technique to apply to which problem. Practice switching between them.
